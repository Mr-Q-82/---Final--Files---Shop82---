# Shop82 — Full-Stack E-Commerce Platform

Shop82 is a full-stack e-commerce project built for selling computer hardware, gaming products, and related accessories. It includes a customer-facing storefront, a dedicated React administration panel, and a Django REST API.

The project is designed as a practical store management system rather than a UI-only demo. Product catalog management, authentication, orders, inventory, payments, content management, reporting, backup and restore, and customer services are connected through the same API.

> **Project status:** Active development  
> **Default language:** Persian (RTL)  
> **Main branch:** `main`

## درباره پروژه

Shop82 برای مدیریت یک فروشگاه واقعی قطعات کامپیوتر طراحی شده است. اطلاعات محصول، قیمت، موجودی، سفارش، پرداخت و محتوای سایت از API خوانده می‌شوند و داخل کد فرانت‌اند ثابت نشده‌اند. به همین دلیل مدیر فروشگاه می‌تواند بدون ویرایش کد، بیشتر بخش‌های سایت را از پنل مدیریت تغییر دهد.

این پروژه دو کاتالوگ مرتبط اما مستقل دارد:

- محصولات عادی برای کاربران عمومی
- محصولات گیمینگ با صفحه، پیشنهادها و محتوای مخصوص

هر دو کاتالوگ از مدل داده مشترک استفاده می‌کنند، اما درخواست‌ها و فیلترهای آن‌ها از هم جدا شده‌اند تا محصول عادی به‌اشتباه در صفحه گیمینگ و محصول گیمینگ در فهرست عادی نمایش داده نشود.

### اهداف اصلی

- فراهم‌کردن مسیر کامل از تعریف محصول تا تحویل سفارش
- امکان مدیریت سایت بدون استفاده روزمره از Django Admin
- حفظ سرعت فروشگاه با بارگذاری تنبل صفحات و درخواست‌های هدفمند
- پشتیبانی درست از زبان فارسی، راست‌چین و داده‌های ایران
- نگهداری‌پذیری کد با تفکیک صفحات، سرویس‌ها و منطق‌های اصلی
- امکان اجرای محلی، Docker و استقرار Production

### محدوده پروژه

Shop82 یک فروشگاه **Single Vendor** است. قابلیت چندفروشندگی در آن وجود ندارد و قیمت، موجودی، ارسال و سفارش‌ها توسط مدیران همان فروشگاه کنترل می‌شوند.

## معماری و جریان داده

معماری پروژه به‌صورت API-first پیاده‌سازی شده است. فروشگاه و پنل مدیریت هر دو مصرف‌کننده API هستند و منطق حساس تجاری در بک‌اند نگهداری می‌شود.

```text
Storefront / Admin Panel
          │
          ▼
   REST API + JWT Auth
          │
          ├── Accounts and Permissions
          ├── Catalog and Search
          ├── Orders and Payments
          ├── Inventory and Operations
          └── Content and Reports
          │
          ▼
 PostgreSQL + Media Storage
          │
          └── Redis / Celery Background Tasks
```

### مسئولیت لایه‌ها

| لایه          | مسئولیت                                                |
| ------------- | ------------------------------------------------------ |
| Storefront    | نمایش فروشگاه، جست‌وجو، سبد، حساب کاربری و خرید        |
| Admin Panel   | مدیریت داده‌ها، گزارش‌ها، محتوا و عملیات فروشگاه       |
| API           | اعتبارسنجی، مجوزها، قرارداد ورودی و خروجی و مدیریت خطا |
| Services      | عملیات تراکنشی مانند سفارش، موجودی، پرداخت و ریستور    |
| Selectors     | Queryهای بهینه و خواندن داده بدون تغییر وضعیت          |
| Database      | نگهداری داده‌های اصلی و روابط فروشگاه                  |
| Media Storage | نگهداری تصاویر محصولات، دسته‌ها، بنرها و پیوست‌ها      |
| Celery        | اجرای کارهای زمان‌بر و زمان‌بندی‌شده در پس‌زمینه       |

### اصول پیاده‌سازی

- عملیات مالی و تغییر موجودی در تراکنش دیتابیس انجام می‌شوند.
- دسترسی پنل مدیریت فقط با نقش و Permission مناسب امکان‌پذیر است.
- فرانت‌اند نتیجه API را نمایش می‌دهد و منبع اصلی داده محسوب نمی‌شود.
- صفحات سنگین و داده‌های دسته‌ها فقط هنگام نیاز بارگذاری می‌شوند.
- خطاهای API ساختاریافته‌اند تا فرم بتواند خطای هر فیلد را جدا نشان دهد.
- فایل‌های آپلودی با مسیر قابل پیش‌بینی و مستقل از سیستم‌عامل ذخیره می‌شوند.

## نصب و اجرای پروژه

### پیش‌نیازها

برای اجرای دستی پروژه موارد زیر لازم است:

- Python 3.10 یا جدیدتر

- Docker Desktop
- Docker Compose

---

### ۱. راه‌اندازی بک‌اند در Windows

از پوشه اصلی پروژه وارد بک‌اند شوید:

```powershell
cd backend
py -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
copy .env.example .env
```

در PostgreSQL یک دیتابیس ایجاد کنید:

```sql
CREATE DATABASE shop82;
```

سپس مشخصات دیتابیس را در `backend/.env` وارد کنید:

```env
DATABASE_NAME=shop82
DATABASE_USER=postgres
DATABASE_PASSWORD=your-postgres-password
DATABASE_HOST=localhost
DATABASE_PORT=5432
```

مایگریشن‌ها را اجرا کرده و مدیر اولیه را بسازید:

```powershell
python manage.py migrate
python manage.py createsuperuser
python manage.py seed_demo
python manage.py runserver
```

API در آدرس زیر اجرا می‌شود:

```text
http://127.0.0.1:8000/api/v1/
```

### ۲. راه‌اندازی بک‌اند در Linux/macOS

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py createsuperuser
python manage.py seed_demo
python manage.py runserver
```

---

### ۳. راه‌اندازی فرانت‌اند

در یک ترمینال جداگانه:

```bash
cd frontend
npm install
npm run build
python dev_server.py
```

آدرس‌های محلی:

| بخش          | آدرس                            |
| ------------ | ------------------------------- |
| فروشگاه      | `http://127.0.0.1:5500/`        |
| پنل مدیریت   | `http://127.0.0.1:5500/admin`   |
| صفحه گیمینگ  | `http://127.0.0.1:5500/gaming`  |
| راهنمای خرید | `http://127.0.0.1:5500/guides`  |
| API          | `http://127.0.0.1:8000/api/v1/` |

اگر API روی آدرس دیگری اجرا می‌شود، می‌توانید در Console مرورگر آدرس آن را تنظیم کنید:

```js
localStorage.setItem('api_base', 'http://127.0.0.1:8000/api/v1')
location.reload()
```

---

### ۴. اجرای سرویس‌ها با Docker

فایل Compose سرویس‌های PostgreSQL، Redis، Django، Celery Worker و Celery Beat را اجرا می‌کند:

```bash
docker compose up --build
```

پس از آماده‌شدن سرویس‌ها، بک‌اند در `http://127.0.0.1:8000` در دسترس است. فرانت‌اند را جداگانه از پوشه `frontend` اجرا کنید:

```bash
cd frontend
npm install
npm run build
python dev_server.py
```

برای توقف سرویس‌ها:

```bash
docker compose down
```

برای حذف Volumeهای دیتابیس و Redis نیز می‌توان از دستور زیر استفاده کرد؛ این دستور داده‌های محلی Docker را حذف می‌کند:

```bash
docker compose down -v
```

## تنظیم متغیرهای محیطی

فایل نمونه تنظیمات در `backend/.env.example` قرار دارد. مهم‌ترین گزینه‌ها:

| متغیر                     | توضیح                                             |
| ------------------------- | ------------------------------------------------- |
| `DJANGO_SECRET_KEY`       | کلید امنیتی Django؛ در Production حتماً تغییر کند |
| `DJANGO_DEBUG`            | در سرور واقعی باید `False` باشد                   |
| `DJANGO_ALLOWED_HOSTS`    | دامنه‌های مجاز بک‌اند                             |
| `DATABASE_*`              | اطلاعات اتصال PostgreSQL                          |
| `CORS_ALLOWED_ORIGINS`    | آدرس‌های مجاز فرانت‌اند                           |
| `REDIS_URL`               | اتصال Redis برای کش و سرویس‌های پس‌زمینه          |
| `SMS_BACKEND`             | حالت `console` یا `kavenegar`                     |
| `PAYMENT_PROVIDER`        | حالت `mock` یا `ZARINPAL`                         |
| `SENTRY_DSN`              | اتصال اختیاری Sentry                              |
| `AWS_STORAGE_BUCKET_NAME` | ذخیره اختیاری فایل‌ها روی فضای S3-compatible      |

هیچ‌وقت فایل `.env`، کلید پیامک، اطلاعات درگاه یا رمز دیتابیس را در GitHub قرار ندهید.

## بکاپ و بازیابی

بکاپ کامل شامل داده‌های فروشگاه و تصاویر است:

```bash
cd backend
python manage.py backup_store
```

فایل خروجی در `backend/backups` ذخیره می‌شود. همین عملیات از بخش «بکاپ کامل» پنل مدیریت نیز در دسترس است.

پیش از Restore، سیستم یک بکاپ ایمنی با پیشوند `before-restore-full` می‌سازد. بااین‌حال، برای محیط Production توصیه می‌شود فایل بکاپ را در فضای جداگانه نیز نگهداری کنید.

### اطلاعات داخل بکاپ کامل

- کاربران و نقش‌ها
- محصولات، دسته‌بندی‌ها و برندها
- سفارش‌ها، پرداخت‌ها و تراکنش‌ها
- تنظیمات و محتوای قابل مدیریت سایت
- تصاویر و فایل‌های پوشه Media

### نکات مهم بازیابی

1. فایل بکاپ را تغییر نام ندهید و محتوای ZIP را دستی ویرایش نکنید.
2. هنگام Restore درخواست مرورگر را متوقف نکنید.
3. فضای خالی دیسک باید بیشتر از حجم فایل بکاپ و Media باشد.
4. پس از پایان عملیات، تصاویر و تعداد رکوردهای مهم را بررسی کنید.
5. بکاپ ایمنی `before-restore-full` را تا پایان بررسی حذف نکنید.

## مروری بر API

Base URL:

```text
/api/v1/
```

| Endpoint                            | کاربرد                   |
| ----------------------------------- | ------------------------ |
| `POST /auth/otp/request/`           | درخواست کد OTP           |
| `POST /auth/otp/verify/`            | تأیید OTP و دریافت توکن  |
| `POST /auth/password/login/`        | ورود با شماره و رمز      |
| `GET/PATCH /auth/me/`               | دریافت یا ویرایش پروفایل |
| `/auth/addresses/`                  | مدیریت آدرس‌ها           |
| `/catalog/categories/`              | دسته‌بندی‌ها             |
| `/catalog/brands/`                  | برندها                   |
| `/catalog/products/`                | محصولات                  |
| `GET /catalog/products/suggest/?q=` | پیشنهاد زنده جست‌وجو     |
| `/catalog/favorites/`               | علاقه‌مندی‌ها            |
| `/catalog/comparison/`              | مقایسه محصولات           |
| `/catalog/reviews/`                 | امتیازها و دیدگاه‌ها     |
| `POST /orders/checkout/`            | ثبت سفارش                |
| `/orders/admin/all/`                | مدیریت سفارش‌ها          |
| `GET /dashboard/overview/`          | خلاصه آمار مدیریت        |
| `/operations/inventory/`            | عملیات انبار             |

تمام APIهای مدیریتی نیازمند احراز هویت و سطح دسترسی مناسب هستند.

### الگوی احراز هویت

درخواست‌های محافظت‌شده به Access Token نیاز دارند. تمدید نشست از مسیر Refresh Token انجام می‌شود و کد فرانت‌اند نباید اطلاعات حساس نشست را در محل ناامن ذخیره کند.

```http
Authorization: Bearer <access-token>
Content-Type: application/json
```

### پاسخ خطا

API بسته به نوع خطا، پیام عمومی و خطاهای فیلدی را برمی‌گرداند. رابط کاربری باید کد وضعیت HTTP را حفظ کند و خطا را به پیام موفق یا خطای ساختگی تبدیل نکند.

| Status | معنی                          |
| ------ | ----------------------------- |
| `400`  | داده ورودی نامعتبر            |
| `401`  | نشست نامعتبر یا پایان‌یافته   |
| `403`  | نداشتن مجوز لازم              |
| `404`  | منبع پیدا نشد                 |
| `409`  | تعارض در عملیات یا وضعیت داده |
| `429`  | تعداد درخواست بیش از حد مجاز  |
| `500`  | خطای داخلی سرور               |

## خطاهای متداول

### تغییرات فرانت‌اند نمایش داده نمی‌شوند

ابتدا فایل‌ها را دوباره Build کنید و صفحه را با `Ctrl + Shift + R` تازه‌سازی کنید:

```bash
cd frontend
npm run build
```

### تصویر آپلودشده نمایش داده نمی‌شود

- بک‌اند باید در حال اجرا باشد.
- آدرس API فرانت‌اند را بررسی کنید.
- در محیط توسعه `DJANGO_DEBUG=True` باشد.
- مسیر ثبت‌شده تصویر باید داخل `backend/media` قرار گرفته باشد.
- تنظیمات CORS و آدرس Media را بررسی کنید.

### خطای migration یا نبودن جدول

```bash
cd backend
python manage.py migrate
python manage.py showmigrations
```

### پنل مدیریت به API متصل نمی‌شود

مطمئن شوید API روی پورت `8000` و فرانت‌اند روی پورت `5500` اجرا شده‌اند و آدرس فرانت‌اند داخل `CORS_ALLOWED_ORIGINS` وجود دارد.

### جست‌وجو نتیجه قدیمی یا دسته اشتباه نشان می‌دهد

ابتدا مطمئن شوید آخرین build فرانت‌اند در حال اجراست. سپس Network مرورگر را بررسی کنید؛ درخواست جست‌وجوی داخل دسته باید `category_id` همان دسته را برای API ارسال کند. در پایان Service Worker و کش مرورگر را با `Ctrl + Shift + R` تازه‌سازی کنید.

### خطای اتصال PostgreSQL

- سرویس PostgreSQL را اجرا کنید.
- نام دیتابیس، کاربر، رمز و پورت `.env` را بررسی کنید.
- وجود دیتابیس را با `psql` یا pgAdmin کنترل کنید.
- پس از اصلاح اتصال، `python manage.py migrate` را دوباره اجرا کنید.

### خطای Redis یا Celery

فروشگاه برای اجرای درخواست‌های عادی می‌تواند بدون Worker بالا بیاید، اما وظایف پس‌زمینه نیازمند Redis و Celery هستند. آدرس `REDIS_URL` و وضعیت Worker را بررسی کنید.
