# ساختار فرانت‌اند فروشگاه 82 — نسخه CSS

این نسخه از CSS آماده استفاده می‌کند و هیچ وابستگی یا مرحله ساخت استایل ندارد.
فایل‌های ظاهری مستقیماً داخل پوشه `css` قرار دارند و با اجرای سرور فرانت‌اند
بارگذاری می‌شوند.

کد React برای اجرای سریع مرورگر به Bundle محلی تبدیل می‌شود. پس از تغییر فایل‌های
`js` دستور `npm run build` را اجرا کنید. فایل‌های آماده داخل `dist/` قرار می‌گیرند
و برای اجرای نسخه تحویلی نیازی به Babel، React یا Leaflet از CDN نیست.

## دسته‌بندی بر اساس کاربری و شخصی‌سازی محصول

در پنل مدیریت، بخش «کاربری و شخصی‌سازی» داخل گروه «کاتالوگ و انبار» قرار دارد.
مدیر می‌تواند برای هر دسته‌بندی و به‌صورت مستقل برای فروشگاه عادی یا گیمینگ،
کاربری‌هایی مانند برنامه‌نویسی، مهندسی، اداری و گیمینگ تعریف کند. گروه‌های انتخابی
مانند پردازنده، RAM و حافظه، اختلاف قیمت، موجودی اختصاصی و گزینه پیش‌فرض نیز از
همین بخش مدیریت می‌شوند.

انتخاب‌های مشتری همراه سبد و سفارش ذخیره می‌شوند، مبلغ نهایی را تغییر می‌دهند و
موجودی گزینه محدود فقط پس از پرداخت موفق کم می‌شود. برای فعال‌شدن ساختار دیتابیس
جدید پس از دریافت پروژه، `python manage.py migrate` را اجرا کنید.

## قوانین کاتالوگ

- فهرست استان‌ها و شهرهای وابسته در `js/shared/data/iran-locations.js` نگهداری می‌شود.
- جداسازی محصولات عادی، گیمینگ و پیشنهاد ویژه در `js/storefront/services/product-selectors.jsx` متمرکز است.
- محصول فقط با فعال‌کردن گزینه «پیشنهاد ویژه» در مدیریت وارد اسلایدر پیشنهادها می‌شود.
- محصول دارای گزینه «گیمینگ» در صفحه اصلی و فروشگاه عمومی نمایش داده نمی‌شود و مخصوص صفحه گیمینگ است.
- API محصولات عادی و گیمینگ را با دو فیلتر صریح دریافت می‌کند تا داده‌های دو کاتالوگ با هم مخلوط نشوند.
- migration شماره `0031` برچسب محصولات گیمینگ قدیمی با SKU رزروشده `GAM-*` را ترمیم می‌کند.

## اعتبارسنجی فرم‌ها

- الگوهای Regular Expression در `js/shared/validation/patterns.js` متمرکز هستند.
- قوانین و پیام دقیق هر فیلد در `js/shared/validation/rules.js` قرار دارد.
- ورود، ثبت‌نام و ورود مدیریت هنگام تایپ، خطای هر ورودی را زیر همان فیلد نمایش می‌دهند.
- همان قواعد حساس نام، شماره، کد دعوت و رمز عبور در API نیز دوباره بررسی می‌شوند.

فرانت‌اند React/Babel را از CDN دریافت می‌کند و استایل‌های آماده مستقیماً از

## مسئولیت پوشه‌ها

- `html`: نقطه‌های ورود فروشگاه و پنل مدیریت.
- `css`: فایل‌های استایل آماده و مستقل برای استفاده مستقیم مرورگر.
- `js/storefront/core`: داده‌های پایه، ابزارها و آیکن‌ها.
- `js/storefront/services`: ذخیره‌سازی، سبد و ابزارهای مرورگر.
- `js/storefront/store`: Context و وضعیت سراسری فروشگاه.
- `js/storefront/components`: اجزای قابل استفاده مجدد رابط فروشگاه.
- `js/storefront/pages`: صفحات خانه، فروشگاه، محصول، ورود، حساب کاربری و
  صفحات محتوایی درباره ما، تماس، سؤالات متداول و شرایط بازگشت.
- `js/admin/core`: ارتباط API و ابزارهای مشترک مدیریت.
- `js/admin/components`: اجزای مشترک مانند مودال تأیید عملیات.
- `js/admin/pages`: هر بخش پنل مدیریت در فایل مستقل.
- `js/shared`: کدهای مستقل از صفحه برای اعتبارسنجی زنده، Regex، نرمال‌سازی و AJAX.
- `bootstrap.js`: فایل‌های JSX را به ترتیب بارگذاری و با Babel اجرا می‌کند.
- `js/api`: ابزار عمومی ارسال درخواست به Django REST API.
- `public`: فایل‌های عمومی مانند manifest برنامه وب.
- `tests`: تست‌های مرورگر Playwright.

## اجرا

برای اجرای تست‌های مرورگر، وابستگی‌ها را نصب کنید:

```bat
cd frontend
npm install
```

سپس سرور فرانت‌اند را اجرا کنید:

```bat
py dev_server.py
```

- فروشگاه: `http://127.0.0.1:5500/`
- مدیریت: `http://127.0.0.1:5500/admin`

## سئو و خروجی Prerender

فرمان `npm run build` علاوه بر Bundleهای قبلی، نسخه‌های HTML دارای عنوان،
توضیحات، canonical، Open Graph، Twitter Card و JSON-LD را داخل
`dist/prerender` می‌سازد. این مرحله ظاهر یا مسیریابی React را تغییر نمی‌دهد.

- اگر Django خاموش باشد، Build بدون خطا ادامه پیدا می‌کند و صفحات ثابت ساخته می‌شوند.
- اگر Django روی پورت ۸۰۰۰ روشن باشد، صفحات محصولات و دسته‌بندی‌ها نیز با اطلاعات
  واقعی پایگاه داده ساخته می‌شوند.
- اجرای لوکال همچنان با `py dev_server.py` و همان آدرس پورت ۵۵۰۰ انجام می‌شود.

برای انتشار، فایل `.env.example` را با نام `.env` کپی و آدرس دامنه را تنظیم کنید:

```env
SEO_SITE_URL=https://example.com
SEO_API_BASE=https://example.com/api/v1
```

در تنظیمات بک‌اند نیز `PUBLIC_SITE_URL` باید همان دامنه عمومی باشد تا لینک‌های
`robots.txt` و `sitemap.xml` صحیح تولید شوند. پوشه‌های داخل `dist/prerender`
باید توسط وب‌سرور برای مسیر متناظر سرو شوند و مسیرهای دیگر همچنان به
`html/index.html` برگردند.
- درباره ما: `http://127.0.0.1:5500/about`
- تماس با ما: `http://127.0.0.1:5500/contact`
- سؤالات متداول: `http://127.0.0.1:5500/faq`
- شرایط بازگشت: `http://127.0.0.1:5500/returns`

سرور توسعه، `/` و `/admin` را به فایل‌های پوشه `html` نگاشت می‌کند؛ بنابراین
آدرس‌های عمومی سایت با این جابه‌جایی تغییر نکرده‌اند.
